# MCLプログラム 使い方マニュアル

ミリ波レーダのデータから、地図構築と自己位置推定(MCL)を行う一式です。

---

## 0. 準備

### 必要なライブラリ

```bash
pip install numpy scipy pandas matplotlib
```

### ファイル構成

| ファイル | 役割 | 直接実行 |
|---|---|---|
| `preprocess.py` | .dat の解読と補正。**全ての起点** | しない(importして使う) |
| `build_corridor_map.py` | 実測寸法から廊下の地図を作る | する |
| `build_map.py` | 汎用の地図生成ツール(区間を並べる形式) | する |
| `mcl.py` | MCL本体 | しない(importして使う) |
| `occupancy.py` | 点群から地図を作る(SLAM側) | しない |
| `egomotion.py` | ドップラーから自分の速度を推定 | しない |
| `run_real.py` | **静止データでMCLを実行** | する |
| `run_moving.py` | **走行データでMCLを実行** | する |
| `test_synthetic.py` | 合成データでMCLの動作確認 | する |
| `map_corridor.npz` | 生成済みの廊下地図 | データ |

## 1. まず動かしてみる(3ステップ)

### ステップ1: 地図を作る

```bash
python3 build_corridor_map.py
```

`map_corridor.npz` が生成されます。廊下の寸法を変えたいときは、
ファイル上部の定数(`Y_CADW` など)を書き換えてから再実行してください。

### ステップ2: 動作確認

```bash
python3 test_synthetic.py
```

人工的に作った観測データでMCLが動くか確認します。
`mcl_synthetic_test.png` が出力され、誤差が数cmに収束していればOKです。

### ステップ3: 実データで実行

```bash
# 静止データ (P1地点の正解位置は x=0.15, y=-0.10, 向き90度)
python3 run_real.py Position1.dat --map map_corridor.npz --true 0.15 -0.10 90

# 走行データ
python3 run_moving.py Run1.dat --map map_corridor.npz --init 0.15 -0.10 90 --motion doppler
```

## 2. 各プログラムの詳しい使い方

### preprocess.py — データの読み込み

全ての処理の入口です。他のスクリプトから呼び出して使います。

```python
from preprocess import parse_dat, to_scan, merge_scans

df = parse_dat("Position1.dat")        # .dat → DataFrame (x,y,z,doppler,snr)
scans = to_scan(df)                    # 補正 → 2D投影 → {フレーム番号: スキャン}
frames = sorted(scans)

s = scans[frames[0]]
s["r"]        # 距離 [m]
s["th"]       # 方位 [rad] (センサ前方=0、左が正)
s["snr"]      # SNR [dB]
s["doppler"]  # ドップラー速度 [m/s]

merged = merge_scans(scans, frames[:15])   # 15フレームを1つに統合
```

**`to_scan()` の中で自動的に行っている補正**

- 距離バイアス −0.16 m (A-1実測)
- 仰角チルト −3.58 度 (A-1実測)
- 高さ ±0.5 m でフィルタして2Dへ投影

オプションで変更できます。

```python
scans = to_scan(df,
                z_band=(-0.5, 0.5),   # 高さの範囲を変える
                snr_min=15,           # SNRの下限を設ける
                doppler_filter=True,  # 静止点だけ残す
                apply_bias=False)     # バイアス補正を切る
```

### build_corridor_map.py — 地図を作る

ファイル上部の定数を実測値に書き換えて実行します。

```python
Y_CADW   = 4.900     # CADサーバ室 西壁の位置
X_N1     = 0.900     # 廊下1 北壁
X_CADN   = -0.900    # 廊下1 南壁 (幅1.8m)
...
```

座標系は「原点 = P1の台車先端、+Y = 進行方向、+X = 右手」です。

**別の場所の地図を作りたい場合**は、代わりに `build_map.py` を使うと、
区間の長さと幅を並べるだけで作れます。

```python
CORRIDOR = {
    "start_heading": 90.0,
    "segments": [
        {"length": 6.35, "width": 1.80, "turn": "L"},   # 直進して左折
        {"length": 3.00, "width": 2.20, "turn": "R"},   # 直進して右折
        {"length": 5.40, "width": 2.71, "turn": None},  # 直進して終端
    ],
    "features": [   # 壁の凹凸
        {"seg": 0, "side": "R", "at": 3.2, "width": 0.6, "depth": 0.25},
    ],
    "start_cap": "open", "end_cap": "open",
}
```

```bash
python3 build_map.py    # map.npz と map_preview.png が出力される
```

**必ず `map_preview.png` を目視確認してください。**
地図の形が実際と違っていると、以降の全てが狂います。

### run_real.py — 静止データでMCL

```bash
python3 run_real.py <録画.dat> [オプション]
```

| オプション | 意味 | 既定値 |
|---|---|---|
| `--map` | 地図ファイル | map.npz |
| `--true X Y DEG` | 正解姿勢(誤差を自動計算) | なし |
| `--merge N` | 統合するフレーム数 | 15 |
| `--zband LO HI` | 高さフィルタの範囲 | -0.5 0.5 |
| `--particles N` | パーティクル数 | 3000 |
| `--out` | 出力画像のファイル名 | mcl_result.png |

**3枚組の図が出力されます。必ず①→②→③の順に見てください。**

1. **地図と観測点群の重ね合わせ** — 壁の位置に点が乗っているか?
   乗っていなければ、地図・座標系・前処理のどれかが誤り。**ここが通らなければ②③に意味はありません。**
2. **尤度地形** — 正解位置(赤星)で尤度が最大になっているか? 観測モデルの検証
3. **パーティクル分布** — 正解の周りに集まっているか? 2山に割れていないか?

コンソールには最尤姿勢、正解との誤差、**2位との尤度差**が出ます。
尤度差が小さい場合は対称解と競合しているので、`--merge` を増やしてください。

### run_moving.py — 走行データでMCL

```bash
# ドップラーから自己速度を推定して使う(推奨)
python3 run_moving.py Run1.dat --init 0.15 -0.10 90 --motion doppler

# 一定速度を仮定する
python3 run_moving.py Run1.dat --init 0.15 -0.10 90 --motion const --speed 0.3

# 正解軌跡と比較する
python3 run_moving.py Run1.dat --init 0.15 -0.10 90 --gt truth.csv
```

| オプション | 意味 |
|---|---|
| `--init X Y DEG` | **必須**。出発点の姿勢 |
| `--motion` | doppler / const / none |
| `--speed` | const時の速度 [m/s] |
| `--vmax` | cfgの最大測定速度(既定 0.61) |
| `--step` | 何フレームずつ処理するか(既定 3) |
| `--gt` | 正解軌跡CSV (`t,x,y` の3列) |

正解軌跡を渡すと、**縦方向誤差と横方向誤差を分けて**出力します。
廊下では縦方向の縮退が焦点なので、この分離が結果の肝になります。

### mcl.py — MCLを自分で組み込む

```python
import numpy as np
from mcl import LikelihoodField, MCL
from preprocess import parse_dat, to_scan, merge_scans

lf = LikelihoodField("map_corridor.npz")
scans = to_scan(parse_dat("Run1.dat"))
frames = sorted(scans)

m = MCL(lf, n_particles=4000, temperature=3.0)
m.init_around(0.15, -0.10, 90)          # 出発点が分かっている場合

for i in range(0, len(frames) - 3, 3):
    sc = merge_scans(scans, frames[i:i+3])
    m.predict(dx=0.02)                   # 3フレーム分の前進量 [m]
    m.update(sc["r"], sc["th"], sc["snr"])
    pose, mass = m.estimate_mode()
    print(f"{pose[0]:+.2f}, {pose[1]:+.2f}, {np.degrees(pose[2]):+.0f}°")
```

**初期化の3通り**

```python
m.init_around(x, y, heading_deg)                    # 位置が分かっている
res = m.init_from_search(r, th, snr)                # 地図全体を総当たり(推奨)
m.init_global(headings=[0, 90, 180, 270])           # ランダムに撒く
```

**推定値の取り出し**

```python
pose = m.estimate()                # 全体の重み付き平均
pose, mass = m.estimate_mode()     # 最大クラスタの平均(推奨)
d_m, d_deg = m.spread()            # 広がり(収束判定用)
```

`estimate_mode()` の `mass` が 0.5 を下回ったら、候補が複数箇所に割れている警告です。

### occupancy.py — 点群から地図を作る(SLAM側)

MCLとは逆に、位置が分かっている前提で地図を作ります。

```python
from occupancy import build_local_map
g = build_local_map(scans, sorted(scans)[:3000])
P = g.prob()      # 0〜1の占有確率マップ

# 複数地点を統合する場合
from occupancy import OccupancyGrid
g = OccupancyGrid(size_m=26, res=0.05)
for f in frames:
    s = scans[f]
    g.integrate(s["r"], s["th"], s["snr"], pose=(x, y, np.radians(heading)))
```

### egomotion.py — ドップラーから自分の速度

```python
from egomotion import estimate_velocity

e = estimate_velocity(s["r"], s["th"], s["doppler"], v_max=0.61)
e["vx"]        # 前進速度 [m/s]
e["ok"]        # 信頼できるか
e["ratio"]     # インライア率
```

RANSACで外れ値(歩行者・ゴースト)を除外します。
`v_max` の8割を超える推定値は自動的に棄却されます。

## 3. パラメータ調整の指針

うまくいかないときに触る順番です。

| 症状 | 対処 |
|---|---|
| 推定が暴れる | `temperature` を上げる(3→10) |
| 推定が追従しない | `temperature` を下げる、`motion_noise` を上げる |
| パーティクルが1点に潰れる | `resample_thresh` を下げる(0.5→0.3) |
| 外れ値に引っ張られる | `LikelihoodField(z_rand=0.3)` に上げる |
| 計算が遅い | `n_particles` を減らす |
| 点が少なすぎる | `--merge` を増やす、CFAR閾値を下げて録画し直す |

## 4. トラブルシューティング

| 症状 | 原因の候補 | 対処 |
|---|---|---|
| ①の図で点が壁に乗らない | 座標軸の取り違え | X/Yの定義、heading の基準を確認 |
| ①で点が全体にずれる | 地図の実測ミス | 幅・長さを測り直す |
| ①で点が一定量ずれる | 前処理の補正値 | `preprocess.py` の `RANGE_BIAS` / `TILT_DEG` |
| ②で正解が最大でない | 観測モデル | `--merge` を増やす、地図を見直す |
| ③が2山に割れる | 対称解 | フレーム統合数を増やす、曲がり角に近い点で試す |
| 移動で発散 | 動作モデル | `--motion const` で試す、速度を確認 |
| ドップラー速度が0ばかり | 速度がv_max付近 | ゆっくり押す、v_maxを広げたcfgで録り直す |

## 5. 既知の制約

- **曲がり角でMCLが破綻します。** レーダーは回転を測れないため、
  回転量は外から与える必要があります。現状は「停止区間の中央で瞬時に90度」
  という粗い仮定なので、IMUの追加が根本的な解決策です。
- 1フレームあたり数点しか得られないため、単一フレームでは自己位置が定まりません。
  5〜15フレームの統合が前提です。
- 窓ガラス越しの反射など、地図に無い点が2〜3割混じります。
  尤度モデルの一様項(`z_rand`)で吸収していますが、完全ではありません。
